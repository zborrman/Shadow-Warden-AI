# THIS FILE DECIDES EVERY VERSION THAT SHIPS.
# requirements.txt states intent (floors, `>=`); this file states the answer.
# It is the single lockfile for the project — there is no second one.
#
# Usage (CI, the Docker image and pip-audit all do this):
#   pip install -r warden/requirements.txt -c warden/constraints.txt
# Constraints only pin versions of packages being installed — they never
# force-install anything, so Linux-only entries are harmless on Windows.
#
# Why it also governs the image (P-0, 2026-07-27): until now only CI passed
# `-c`, while warden/Dockerfile installed requirements.txt bare. The two sets
# drifted apart — a measurement on 2026-07-27 found *48* packages differing
# between the CI-tested set and the running production image. One of them,
# prometheus-fastapi-instrumentator (CI 8.0.2 / prod 8.1.0), changed the arity
# of `_get_route_name` and 502'd the entire API on 2026-07-26. The other 47
# were the same accident waiting for a rebuild. The Dockerfile now passes `-c`.
#
# THIRD-PARTY SCANNERS CANNOT SEE THIS FILE. `constraints.txt` is not a name any
# SCA tool globs for, so anything scanning this repo from the outside reads the
# `>=` floors in requirements.txt and reports a dependency set that has never
# shipped. CodeRabbit's OSV Scanner did exactly that on 2026-07-30 — 12 phantom
# Critical/High findings, most on packages (aiohttp, ecdsa, pyarrow, torch) that
# have never been in requirements.txt at all, with versions chosen by string sort
# rather than PEP 440: aiohttp 3.9.5 "over" 3.14.1, pyarrow 9.0.0 "over" 24.0.0.
# It is disabled in .coderabbit.yaml for that reason.
#
# Before believing any external dependency dashboard, audit THIS file:
#   pip install -r warden/requirements.txt -c warden/constraints.txt && pip-audit
# which is what the gating `pip-audit (SCA)` CI job already does.
#
# EXCLUDED, pinned explicitly in warden/Dockerfile instead:
#   torch          — the `+cpu` local version only exists on the PyTorch CPU
#                    index and cannot be resolved from PyPI via constraints.
#   liboqs-python  — source build (cmake), installed fail-open before step 3.
#

# torch, replace everything below the header. Then redeploy — do not hand-edit
# individual versions to match production; production is the thing being
# corrected, not the reference.
#
